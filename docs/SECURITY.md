# ความปลอดภัย — MOF PSDG AI Chatbot

ระบบนี้ออกแบบภายใต้หลัก **Security by Design** เพื่อปกป้องข้อมูลราชการและรักษาความปลอดภัยของผู้ใช้งาน

## มาตรการความปลอดภัยที่ใช้

### 1. การยืนยันตัวตน (Authentication)
- รหัสผ่านถูกแฮชด้วย **bcrypt** ก่อนจัดเก็บในฐานข้อมูล
- ใช้ **JWT (JSON Web Token)** สำหรับการยืนยันตัวตนใน API
- Token หมดอายุตามที่กำหนดใน environment variable (ค่าเริ่มต้น 60 นาที)
- ระบบล็อกบัญชีชั่วคราวเมื่อพยายามล็อกอินผิดเกินจำนวนครั้งที่กำหนด

### 2. การควบคุมการเข้าถึง (Authorization)
- **RBAC (Role-Based Access Control)** แบ่งสิทธิ์เป็น 4 ระดับ:
  - `super_admin`: จัดการทุกอย่างในระบบ
  - `admin`: จัดการเอกสาร, ผู้ใช้, ลิงก์ทดลอง, การตั้งค่า AI
  - `editor`: อัปโหลดและแก้ไขเอกสาร, จัดการเว็บไซต์แหล่งข้อมูล
  - `viewer`: ดูข้อมูลได้อย่างเดียว ไม่สามารถแก้ไขได้
- ทุก API endpoint ตรวจสอบสิทธิ์จาก backend ก่อนอนุญาตให้เข้าถึง

### 3. การป้องกันช่องโหว่ทั่วไป
- **SQL Injection**: ใช้ SQLAlchemy ORM ซึ่งป้องกันการโจมตี SQL injection โดยอัตโนมัติ
- **XSS (Cross-Site Scripting)**: Frontend ใช้การ escape HTML ก่อนแสดงข้อความจากผู้ใช้
- **CSRF (Cross-Site Request Forgery)**: ต้องมีการป้องกัน CSRF สำหรับการเปลี่ยนแปลงสถานะ
- **Path Traversal**: ตรวจสอบชื่อไฟล์ก่อนบันทึกลงดิสก์ ป้องกันการเข้าถึงไฟล์นอกโฟลเดอร์ที่กำหนด
- **Input Validation**: ตรวจสอบข้อมูลทุกอย่างที่รับจากผู้ใช้ก่อนประมวลผล

### 4. การจัดการความลับ (Secrets Management)
- API Key, Secret Key, และข้อมูลที่ละเอียดอ่อนทั้งหมดต้องเก็บในไฟล์ `.env`
- ห้ามนำไฟล์ `.env` ขึ้น Git repository
- ห้ามเขียน secret ลงใน source code โดยตรง
- Frontend ไม่มีสิทธิ์เข้าถึง API Key โดยเด็ดขาด

### 5. การจำแนกความลับของเอกสาร
เอกสารในฐานความหู้ถูกจำแนกเป็น 2 ระดับ:

| ระดับ | คำอธิบาย | การเข้าถึง |
|-------|----------|------------|
| PUBLIC | เผยแพร่สาธารณะ | ผู้ใช้ทั่วไปสามารถเข้าถึงได้ |
| INTERNAL | เฉพาะภายในหน่วยงาน | เฉพาะผู้มีสิทธิ์ editor ขึ้นไปเท่านั้น |

เอกสาร INTERNAL ตะไม่ถูกนำไปใช้ตอบผู้ใช้งานสาธารณะ

### 6. การป้องกัน Prompt Injection
- เนื้อหาเอกสารถูกใช้เป็นข้อมูลประกอบการค้นหาเท่านั้น
- เนื้อหาเอกสารไม่มีอำนาจเหนือ System Prompt
- ระบบตรวจจับและกรองคำสั่งที่อาจแทรกแซงการทำงานของ AI

### 7. Audit Logging
บันทึกการกระทำสำคัญทั้งหมดในระบบ:
- การเข้าสู่ระบบและออกจากระบบ
- การอัปโหลดและลบเอกสาร
- การเปลี่ยนแปลงการตั้งค่า AI
- การสร้างและยกเลิกลิงก์ทดลอง
- การเข้าถึงข้อมูลที่ละเอียดอ่อน

### 8. Rate Limiting
จำกัดจำนวนคำขอต่อนาทีสำหรับแต่ละ API endpoint เพื่อป้องกันการโจมตีแบบ DoS

### 9. Trial Link Security
- ใช้ **secure random token** สำหรับลิงก์ทดลอง
- Token ถูกแฮชก่อนจัดเก็บในฐานข้อมูล
- ลิงก์ทดลองไม่เปิดเผย Admin Dashboard
- ผู้ใช้ผ่านลิงก์ทดลองไม่มีสิทธิ์แก้ไขฐานความรู้
- ปิดการจัดทำดัชนีจาก Search Engine (noindex, nofollow)

## คำแนะนำสำหรับการ Deploy

1. เปลี่ยน `SECRET_KEY` ในไฟล์ `.env` เป็นสตริงสุ่มที่ปลอดภัย
2. กำหนด `DEBUG=False` ใน production
3. ใช้ HTTPS ใน production
4. จำกัด CORS ให้เฉพาะ domain ที่เชื่อถือได้
5. สำรองข้อมูลฐานข้อมูลเป็นประจำ
6. ตรวจสอบ audit logs เป็นระยะ
